# 概念 22 - 暴风吸入与逐字斟酌：预填（Prefill）与解码（Decode）的物理节律

---

## 老师引言：为什么大模型读得飞快，写起来却一顿一顿的？

如果你经常使用 ChatGPT、Claude 或 DeepSeek，你一定观察过这个奇妙的现象：
当你复制粘贴一段长达 5000 字的长篇大论扔给模型，然后按下回车——模型几乎在**一眨眼的瞬间（不到半秒）**，就完全“读完”了这 5000 字！
但紧接着，当它开始给你回答时，屏幕上却是一个字、一个字地往外蹦（每秒钟吐出 30 到 50 个字），像个打字员在键盘上逐字敲击。

为什么大模型“读”的时候像狂风卷落叶，而“写”的时候却慢如溪水长流？
今天，老师就带你走进大模型推理生命周期中最基础也最关键的双重节奏——**预填阶段（Prefill）** 与 **解码阶段（Decode）**。

---

## 生活实体模型：速读题干的学生与考场交卷的考生

想象一位参加全国高考的学霸坐在考场里：

### 1. 预填阶段（Prefill）：暴风吸入题干
试卷发下来，第一道阅读理解题有整整 3000 字的背景材料。
学霸把试卷平铺在桌面上，双眼一扫，两目十行，大脑里的数万个神经突触全速运转：
- 题干里的这 3000 个字，**早就白纸黑字印在纸上了**；
- 他的大脑可以**同时、全量、并行地**将整篇文章的所有词语及其相互关系一口气吞下，并在脑海草稿纸上瞬间建立起整篇文章的认知地图。
这个“把已知题目瞬间吃透、在大脑中建好上下文记忆”的过程，就叫做**预填（Prefill）**！

### 2. 解码阶段（Decode）：如履薄冰逐字作答
题干看完了，接下来学霸必须开始动笔在答卷上写下他的分析长文。
但问题来了：**他能同时把第 1 句话、第 5 句话和第 10 句话一口气写在卷子上吗？**
绝对不能！
因为他必须先想出第 1 个字；根据第 1 个字的意思，才能推敲出第 2 个字；等第 1 句话写完，他才能决定第 2 句话怎么开头！
每一个新字，都必须依赖前面所有已经写下的字。
这个“每次只能闭目沉思、吐出唯一一个新字，再把它加入上文继续构思下一个字”的漫长过程，就叫做**逐字解码（Decode）**！

---

## 它在大模型里到底怎么工作？

在大模型的硬件芯片（GPU）上，这两个阶段所面临的物理瓶颈完全天差地别：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        大模型推理的两副完全不同的面孔                  │
├────────────────────────────────────────────────────────────────────────┤
│ 阶段一：预填阶段 (Prefill)                                              │
│   输入: 用户发来的整段长提示词 (例如 4000 个已知 Token)                │
│   特征: 答案都在眼前，整块矩阵一起算 (大尺寸 GEMM)                     │
│   硬件状态: GPU 的成千上万个计算核心瞬间被喂得饱饱的 (算力受限 Compute-Bound)│
│   耗时: 极短，几乎不卡顿                                               │
├────────────────────────────────────────────────────────────────────────┤
│ 阶段二：解码阶段 (Decode)                                               │
│   输入: 每次仅仅输入刚刚生成的 1 个最新 Token                          │
│   特征: 必须等上一个字吐出，才能算下一个字 (细长向量矩阵乘 GEMV)       │
│   硬件状态: 算力核心饥肠辘辘，全程在干等显存把庞大权重搬运过来 (访存受限)│
│   耗时: 取决于要生成多少字，字数越多耗时越长                           │
└────────────────────────────────────────────────────────────────────────┘
```

硬件科学家用一个非常形象的指标来衡量这两个阶段的物理状态——**算术强度（计算访存比）**：
- 在 **Prefill** 阶段，模型把数百亿参数从显存读入芯片一次，就能同时为 4000 个词语做几万亿次并行乘加，算力利用率高达 80% 以上！
- 在 **Decode** 阶段，模型为了算仅仅 **1 个新字**，仍然不得不把整整几百亿参数从显存里完整搬出来一遍！GPU 的计算核心只花了 1% 的时间做计算，剩下 99% 的时间都在百无聊赖地干等数据总线搬运。

---

## 如果拿掉它，世界会怎样？

如果我们无法理清 Prefill 和 Decode 的物理区别：
- 工程师就会把读长文章的任务和写简短回答的任务混杂在同一张显卡里，导致正在流畅打字的系统突然因为别人发来一篇长文而剧烈卡顿好几秒；
- 硬件厂商就会盲目堆叠计算核心，却不知道解码阶段的真正痛点是显存总线太狭窄。
正是因为认清了这两个阶段的本质差异，才催生了现代所有大模型推理加速技术的爆发！

---

## 老师划重点

!!! tip "核心心法"
    **预填（Prefill）是全量并行的饕餮盛宴，榨干 GPU 的算力核心；解码（Decode）是单字串行的漫长独木桥，受制于显存的搬运带宽。大模型的所有推理优化，本质上都是在向这两个物理瓶颈发起进攻！**
