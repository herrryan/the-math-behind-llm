# 概念 23 - 显存记事本与带宽墙：KV Cache 膨胀与分组记忆瘦身（GQA / MLA）

---

## 老师引言：为什么大模型聊得越久，你的显存越容易被撑爆？

很多人以为，大模型运行时占用的显存大小是固定不变的。
比如一个 70B（700 亿参数）的模型，权重文件大约占 140 GB 显存，那是不是只要有 140 GB 显存就万事大吉了？

绝对不是！当你兴致勃勃地让大模型读一本几十万字的厚书，或者跟它多轮对话聊了一下午之后，你会惊恐地发现显存报警器突然拉响，程序直接崩掉并提示：`CUDA Out of Memory`！
那些凭空冒出来的几十上百 GB 显存到底被谁吃掉了？
答案就是大模型赖以生存的**思维记事本——KV Cache（键值缓存）**。

---

## 生活实体模型：鱼的 7 秒记忆与贴满书房的便利贴

想象你雇佣了一位极其聪慧但天生患有“顺行性遗忘症”的顾问：
这位顾问每思考完一句话，就会把刚才思考的精髓写在便利贴上。

### 1. 如果没有记事本（没有 KV Cache）：推倒重来的地狱
每次你问他一个新问题，或者让他接着上一句写：
他必须从你今天早晨对他说过的第一声“你好”开始，重新把几千句话的逻辑在大脑里从头到尾全部运算推演一遍！
- 第 1 个字，他算了 1 句话；
- 第 100 个字，他必须重新算 100 句话；
- 第 10,000 个字，他为了吐出这一个字，必须重复计算整整 10,000 句话的前置逻辑！
整个系统的计算量会呈二次方（$N^2$）失控爆炸，吐字速度会越来越慢，最后慢到几分钟才憋出一个字。

### 2. 备上随身记事本（有了 KV Cache）：只记增量
为了避免重复劳动，顾问想出了好办法：
每当他读完或写完一个词，就把自注意力机制里算出来的**“线索索引（Key）”**与**“知识内容（Value）”**工工整整写在一张便利贴上，贴在桌子旁。
当下一次要算新词时，历史便利贴直接拿来查阅，自己只需要为眼前这 **1 个最新词** 算一张新便利贴就行了！
计算量瞬间从二次方雪崩变成了轻松的线性增长！

### 3. 便利贴灾难：书房被纸条彻底淹没！
可是，便利贴虽然省下了大量的脑力重复计算，代价却是物理空间的恐怖膨胀：
在大模型里，每一层网络、每一个注意力头、每一个生成的词语，都必须留下一份 KV 便利贴。
当上下文长度达到 128k（13 万字）时，光是这叠便利贴的重量就高达 **数百吉字节（GB）**，甚至远远超过了模型本身的所有参数总和！

---

## 它在大模型里到底怎么工作？

为了不让显存记事本把服务器撑爆，科学家们发明了革命性的“记事本瘦身术”：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        三代注意力记事本 (KV Cache) 演进                │
├────────────────────────────────────────────────────────────────────────┤
│ 1. 传统多头注意力 (MHA): 每个提问者配专职书童                         │
│    查询头 (Q):  [Q0]  [Q1]  [Q2]  [Q3]  [Q4]  [Q5]  [Q6]  [Q7]         │
│    键值头 (KV): [K0]  [K1]  [K2]  [K3]  [K4]  [K5]  [K6]  [K7] (超占显存)│
│                                                                        │
│ 2. 分组查询注意力 (GQA - LLaMA 3 标配): 多人共用一个共享书童          │
│    查询头 (Q):  [Q0   Q1   Q2   Q3]     [Q4   Q5   Q6   Q7]            │
│    键值头 (KV):         [KV 0]                    [KV 1]               │
│    ──► 显存占用直接砍掉 4 到 8 倍！性能几乎不降！                      │
│                                                                        │
│ 3. 多头潜在注意力 (MLA - DeepSeek 独门绝技): 压缩暗号记事本            │
│    不论上方有多少个查询头，写入显存的 KV 记事本被强行压扁成一个微小暗号│
│    ──► 显存占用暴降近 90%！长文本推理性价比之王！                      │
└────────────────────────────────────────────────────────────────────────┘
```

1. **标准 MHA（多头注意力）**：每一个提问头（Query Head）都拥有自己专属的 Key 和 Value。头数越多，记事本越厚。
2. **GQA（分组查询注意力）**：让 4 个或 8 个提问头共享同一本 Key-Value 记事本。显存占用直降至原来的八分之一，成为现代大模型工业界的事实标准。
3. **MLA（多头潜在注意力，DeepSeek 核心精髓）**：在把 Key 和 Value 存入显存前，用一把数学压缩钳将其压扁成一个超紧凑的潜在低维向量；只在需要使用的一瞬间动态还原。

---

## 如果拿掉它，世界会怎样？

如果没有 KV Cache，大模型的长文本推理将彻底不可用——生成一千字的回复可能需要好几个小时；
而如果没有 GQA 和 MLA 这些记事本压缩黑科技，我们就无法在单台服务器上体验 128k 甚至百万 Token 的超长文本分析，普通用户更不可能在个人电脑上跑起长对话助手。

---

## 老师划重点

!!! tip "核心心法"
    **KV Cache 是一场用空间换时间的精密交换：它用显存里的记事本消除了重复计算的历史噩梦；而 GQA 与 MLA 则是记事本的极限压缩术，把显存从无底洞般的内存墙中解救了出来。**
