# 概念 25 - 芯片片上的闪电速记：FlashAttention 为何将数据搬运视为终极死敌

---

## 老师引言：最快的计算，是压根不需要跑腿的计算

在计算机世界里，有一个反直觉却残酷无比的真相：
**GPU 做数学加减乘除的速度，比它从自己的显存仓库里取放数据的速度，快了整整几十甚至上百倍！**

如果你让 GPU 的计算核心算 100 亿次乘法，它只需要微秒级别就能完成；但如果你让它把这 100 亿个数字从显存大仓库搬到计算核心，再把算好的结果运回大仓库，它可能要在路上气喘吁吁地跑好几倍的时间。
现代计算的本质悲剧，不是算得慢，而是**“快递小哥在路上堵死了”**。
而 **FlashAttention（闪速注意力）**，就是一场向数据搬运发起的全面宣战。

## 生活实体模型：随手案板与三公里外的冷库

想象你是一位刀工出神入化的五星级大厨：
在你的手边，有一个面积虽然很小、但一伸手就能抓到的**超高速案板（芯片片上 SRAM 缓存，带宽每秒近 20 TB）**；
而在后院三公里外，坐落着一个面积巨大、什么都能装下的**大冷库（显存大仓库 HBM，带宽只有每秒 3 TB 左右）**。

### 1. 传统注意力的笨办法：跑步两小时，做菜五分钟
传统计算自注意力机制（Q乘K、算Softmax、乘V）时，步骤是极其笨拙的：
1. 大厨跑到三公里外的冷库，抱出一箱 Query 和一箱 Key 回到案板；
2. 案板上切了一刀，算出了一个巨大的中间相似度打分大方阵；
3. 大厨**竟然又把这个巨大的大方阵哼哧哼哧搬回了三公里外的冷库**！
4. 歇了口气，大厨又跑去冷库把这个大方阵搬出来，在案板上算归一化概率；
5. 算完概率，**又特么搬回了冷库**！
6. 最后，又跑去冷库搬出 Value，把概率方阵从冷库搬出来，两者相乘得到结果。
整顿饭做下来，大厨有 90% 的时间都在大冷库与厨房之间疯狂来回折返跑！更糟糕的是，如果文章有一万字，那个中间大方阵的面积就会达到惊人的一亿个格子，冷库的大门都要被挤爆了。

### 2. FlashAttention 的智慧：就地做熟，绝不搬运中间残次品！
斯坦福大学的 Tri Dao 博士提出了一个颠覆性的想法：
*为什么我们一定要把半成品的中间大方阵搬回大冷库去？*
大厨在案板上只切一小块胡萝卜（一个小分块），直接在案板上完成局部打分、就地归一化、就地乘上局部 Value，**只把最终煮好的精美菜肴送回大仓库**！
中间那些庞大恐怖的半成品，在手边的案板上算完即焚，从始至终压根不需要在大冷库里留下一丝痕迹！

## 它在大模型里到底怎么工作？

读者可能会问：“老师，归一化（Softmax）不是必须知道全局所有词的最大值和总和才能算吗？切成小块之后，你怎么知道后面的词会不会更大？”

这就是 FlashAttention 背后最神仙的技巧——**在线动态归一化（Online Softmax）**：
- 当大厨算完第 1 小块时，先记录下当前的局部最大值和局部和；
- 当读到第 2 小块时，如果发现出现了更大的新数字，大厨并不需要推倒重来，而是掏出一把“数学修正尺”，只用一行极简的小乘法，就能瞬间把第 1 小块的结果原地校准！
这种精巧的数学递推，使得在极小的片上案板（SRAM）里流式消化全局注意力成为了现实。

## 如果拿掉它，世界会怎样？

如果没有 FlashAttention：
- 大模型的训练成本至少要上升 3 到 5 倍，很多千亿规模的开源大模型根本无力完成预训练；
- 长文本处理会变得寸步难行——现在的 32k、128k 上下文窗口之所以能成为现实，正是因为 FlashAttention 把平方级的显存搬运灾难压平到了极低的水准。
它被公认为过去三年深度学习系统领域最伟大的工程里程碑之一。
