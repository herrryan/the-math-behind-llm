# 第 E21 章：投机解码：让轻量小模型大胆猜，让千亿大模型并行核验

同学，你好！在前面我们推导过：大模型在生成时，每生成一个新词，都要把成百上千亿个参数从显存里搬运一遍。

这时候，很多聪明的同学会忍不住拍大腿：“老师，既然每次搬运参数都要花好几毫秒，那如果每次我们能一口气蹦出 3 个甚至 5 个词，这几毫秒不就花得超值了吗？”

你可能会问：“可是大模型是自回归的呀，第 2 个词必须等第 1 个词生成了才能算，怎么可能‘一口气生成好几个词’呢？”

这就是 Google 和 DeepMind 的天才研究员们在 2022 年向全世界亮出的魔法手杖——**投机解码（Speculative Decoding）**！

今天，老师就带你拆解这个让生成速度直接狂飙 2 到 3 倍、而且**输出质量数学绝对无损**的神仙算法！

## 步骤 1：物理直觉（大作家与打字小书童）

老师给你打个文豪写作的比方：

- **文豪亲自单打独斗（传统大模型解码）：**  
  文豪（千亿参数大模型，肚子里学富五车，但动作极其沉稳缓慢）坐在桌前：
  想 1 秒钟，写出“我们”；  
  再想 1 秒钟，写出“必须”；  
  再想 1 秒钟，写出“高度”；  
  再想 1 秒钟，写出“重视”……  
  虽然文笔绝顶，但每憋出一个字都要花整整 1 秒钟。
- **配上轻快的小书童（投机解码模式）：**  
  文豪雇佣了一个手脚极其麻利的小书童（小巧轻快的 1B 参数小模型，动笔如飞）：
  1. **小书童大胆抢答：** 小书童在 0.1 秒内，一口气在草稿纸上猜着往下写了 4 个词：“必须 / 高度 / 重视 / 发展”；
  2. **大文豪一眼扫过（并行核验）：** 文豪戴上老花镜，根本不需要逐字苦思，**只需将这 4 个词打包成一个矩阵乘法，一瞬间扫视核对（Prefill 工况，计算密集，极其迅速！）**；
  3. **裁决时刻：** 文豪点头说：“‘必须’对，‘高度’对，‘重视’也对；但第四个词我不打算用‘发展’，我想用‘安全’！”
  4. 于是，文豪当场通过了前 3 个词，并在第 4 个词的位置亲自纠偏！

你看，**原本需要文豪枯坐 4 秒钟的事情，现在文豪只需抬手看一眼，在 1 秒多钟内直接收割了 4 个词！**

## 步骤 2：芯片微观底层执行机制

投机解码之所以在物理硬件上能实现暴击加速，是因为它**把慢速的访存密集型 Decode，巧妙转化成了高效的计算密集型短 Prefill！**

```
【投机解码单轮执行闭环时序】

1. 草稿生成阶段 (Drafting):
   轻量级草稿小模型 (如 LLaMA-3 1B) 独立执行 K 步自回归自生:
   产出候选 Token 序列: [x1, x2, x3, x4] (花费微量时间)

2. 目标大模型并行验证 (Target Model Verification):
   目标大模型 (如 LLaMA-3 70B) 一口气将 [当前词, x1, x2, x3, x4] 拼接输入!
   注意: 这是一次小规模的 Prefill 矩阵乘法!
   全模型 700 亿参数依然只从 HBM 读取了一次，
   但在片上 Tensor Core 冲压机里，同时算出了这 4 个位置的全部转移概率分布!

3. 拒绝采样裁决机制 (Rejection Sampling):
   按顺序逐字比对小模型与大模型的输出概率:
   如果 P_target(x) >= P_draft(x)，直接无条件接受!
   如果小模型猜错了，以一定概率拒绝并当场由大模型根据修正分布采样出正确词，
   丢弃后续所有猜想，开启下一轮循环!
```

### 为什么数学上完全绝对无损？
很多初学者最担心的问题是：“小模型水平那么差，大模型会不会被带偏变笨？”  
老师明确告诉你：**绝对不会！**  
Leviathan et al. (2023) 在数学上给出了极其严密的证明：通过精巧的**拒绝采样概率修正公式**，投机解码最终吐出的每一个 Token 的概率分布，**与千亿大模型独立逐字生成的原始概率分布完全数学严格一致！**

## 步骤 3：跨组件相互耦合机制

1. **草稿模型的摆放拓扑：**  
   草稿模型通常只有主模型的几十分之一大小。在单卡推理时，小模型可以直接常驻在同一张显卡显存中；在多卡分布式集群中，小模型甚至可以部署在专门的独立辅助卡上。
2. **接受率（Acceptance Rate $\alpha$）对硬件提速的决定性影响：**  
   小模型猜得越准，平均每步接受的 Token 数量就越多。如果两个模型领域契合度极高（$\alpha > 80\%$），加速比可直奔 3 倍；但如果小模型在生僻领域胡猜导致屡屡被拒，系统就会退化为纯粹的大模型单步执行。

## 步骤 4：精确性能数学公式

设草稿小模型每轮推测生成 $K$ 个 Token。小模型生成单 Token 耗时为 $t_{\text{draft}}$，大模型验证这 $K$ 个 Token 的单次前向耗时为 $t_{\text{target}}$。

设小模型预测的平均接受率为 $\alpha$（$0 \le \alpha \le 1$）。

单轮循环中，期望被接受的有效 Token 数量为：

$$\mathbb{E}[\text{Accepted}] = \sum_{i=1}^K \alpha^i + 1 \quad (\text{最后保底附赠由大模型裁决纠偏的 1 个 Token})$$

单轮循环的硬件总物理耗时为：

$$T_{\text{round}} = K \times t_{\text{draft}} + t_{\text{target}}$$

投机解码相比大模型原始逐字解码的实际理论加速比（Speedup Ratio）为：

$$\text{Speedup} = \frac{\mathbb{E}[\text{Accepted}] \times t_{\text{target}}}{K \times t_{\text{draft}} + t_{\text{target}}}$$

## 步骤 5：具体微基准数字推导

我们来为业界最经典的组合——**主模型 LLaMA-3 70B + 草稿模型 LLaMA-3 8B** 在 8 卡 H100 节点上手算一笔账！

已知实测单步参数：
- 70B 目标模型单次前向耗时：$t_{\text{target}} = 10 \text{ 毫秒}$
- 8B 草稿模型单步前向耗时：$t_{\text{draft}} = 1.5 \text{ 毫秒}$
- 设定草稿步数：$K = 4$
- 实测两者的语义重合接受率：$\alpha = 0.75$（75% 的词都能猜中）

### 1. 计算单轮期望产出 Token 数量
$$\mathbb{E}[\text{Accepted}] = \alpha + \alpha^2 + \alpha^3 + \alpha^4 + 1 = 0.75 + 0.5625 + 0.4219 + 0.3164 + 1 \approx \mathbf{3.05 \text{ 个 Token}}$$
单轮下来，平均一口气蹦出 3 个字！

### 2. 计算单轮硬件总耗时
$$T_{\text{round}} = 4 \times 1.5 \text{ ms} + 10 \text{ ms} = 6 \text{ ms} + 10 \text{ ms} = \mathbf{16 \text{ 毫秒}}$$

### 3. 计算生成每个 Token 的均摊耗时
$$T_{\text{per\_token}} = \frac{16 \text{ 毫秒}}{3.05} \approx \mathbf{5.25 \text{ 毫秒}}$$

### 4. 对比未优化的 70B 单独运行：
原本 70B 单独生成每个字需要死死耗费 $10\text{ 毫秒}$。  
现在的端到端加速比为：

$$\text{Speedup} = \frac{10 \text{ ms}}{5.25 \text{ ms}} \approx \mathbf{1.905 \times！}$$

**整整快了近一倍！** 而且没有牺牲哪怕一丁点模型的智慧与逻辑！
