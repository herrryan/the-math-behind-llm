# 第 E06 章：注意力架构变体深度权衡：MHA、MQA、GQA 与 MLA 的硬件开销与显存对决

同学，你好！在上一节课里，我们算出了一个惊人的数字：单个长对话的 KV Cache 动辄吃掉几个吉字节的显存。

你可能会好奇：“老师，难道为了自回归生成，我们就只能眼睁睁看着显存被 KV 缓存一点点吞噬吗？**我们在模型架构的源头上，能不能想点办法给 KV 向量减减肥呢？**”

问得太好了！过去的五年里，全球顶尖的模型架构师们（Google、Meta、DeepSeek）在这个问题上展开了极其激烈的探索，接连发明了：
- **MHA（Multi-Head Attention，多头注意力）**
- **MQA（Multi-Query Attention，多查询注意力）**
- **GQA（Grouped-Query Attention，分组查询注意力）**
- **MLA（Multi-Head Latent Attention，多头潜在注意力）**

今天这节课，老师就带你站在硬件工程的角度，看看这些缩写背后的**显存与精度的大博弈**！

---

## 步骤 1：物理直觉（公司里的总监与秘书配比）

为了让你秒懂它们之间的区别，老师给你打个职场团队分工的比方：

在注意力机制里，每个 **Query（Q 头）**就像一位负责思考决策的**业务总监**；而 **Key 和 Value（KV 头）**就像给总监提供背景资料的**助理秘书**。

1. **MHA（经典多头注意力）：一对一土豪配置**  
   公司里有 64 位总监（64 个 Q 头），土豪老板给每一位总监都配了一位专属的私人秘书（64 个 K/V 头）。  
   - 优点：每个总监都有专人伺候，看问题的角度完全独立，模型表达能力最强。  
   - 缺点：64 位秘书的工资和工位开销（KV Cache 显存）大得惊人，公司很快就要被吃垮了！
2. **MQA（多查询注意力）：极致抠门的共享秘书**  
   老板为了省钱，把 63 位秘书全给开除了！全公司 64 位总监，**公用仅仅 1 位秘书（1 个 K/V 头）**。  
   - 优点：显存开销直接缩减到原来的 $\frac{1}{64}$，省钱到了极点！  
   - 缺点：所有总监只能看同一份资料，模型的复杂推理能力明显受损，很容易变笨。
3. **GQA（分组查询注意力）：优雅的中庸之道（现代大模型标配）**  
   老板灵机一动：我们折中一下！把 64 位总监分成 8 个小组，每 8 个总监共享 1 位小组秘书（8 个 K/V 头）。  
   - 奇迹出现了：**显存直接砍掉 87.5%（变成原来的 $\frac{1}{8}$），而模型的智力水准几乎毫发无损！**（现在的 LLaMA-2/3、Mistral、Qwen 全面采用这一架构）。
4. **MLA（DeepSeek 的神来之笔：压缩档案袋）**  
   DeepSeek 的工程师更绝：他们不仅分组，还给秘书发了一个**高维无损压缩机**！每次存进显存时，把庞大的资料压缩成一个极小的潜在特征向量（Latent Vector），等总监要看的时候再当场解压！显存再次狂降数倍！

## 步骤 2：芯片微观底层执行机制

我们把目光切回显卡芯片内部：

```
MHA (经典多头注意力):
Q Heads:   [Q0] [Q1] [Q2] [Q3] ... [Q63]  (64 个)
            │    │    │    │        │
KV Heads:  [K0] [K1] [K2] [K3] ... [K63]  (64 个, KV 显存开销 100%)

--------------------------------------------------------------------------------

MQA (多查询注意力):
Q Heads:   [Q0] [Q1] [Q2] [Q3] ... [Q63]  (64 个)
             \    \    │   /        /
KV Heads:            [ K0 ]                (仅 1 个, KV 显存立减至 1/64 = 1.5%)

--------------------------------------------------------------------------------

GQA (分组查询注意力, 如 8 组):
Q Heads:   [Q0..Q7]   [Q8..Q15]   ...   [Q56..Q63]  (64 个 Q 头分成 8 组)
              │           │                  │
KV Heads:    [KV0]       [KV1]    ...       [KV7]       (仅 8 个, KV 显存压缩至 1/8 = 12.5%)

--------------------------------------------------------------------------------

MLA (DeepSeek 多头潜在注意力):
不直接缓存庞大的 K, V 向量!
利用低秩矩阵将其投影并压缩为一个紧凑的低维潜在向量 c_t [维度仅 512]
读取时通过矩阵乘即时解压恢复，同时结合解耦的 RoPE 位置向量!
==> KV Cache 显存占用进一步狂降至 MHA 的 5% 以下!
```

## 步骤 3：跨组件相互耦合机制

架构的改变对硬件推理执行带来了惊天动地的质变：

1. **从访存受限（Memory-Bound）向计算受限（Compute-Bound）大幅跃迁：**  
   在自回归解码中，由于每次只需要从显存搬运 $\frac{1}{8}$（GQA）乃至更少（MLA）的 KV 数据，每个字节对应的有效矩阵计算量大幅上升，**算术强度提升了数倍**！显存带宽总线不再严重堵塞，单步生成延迟（ITL）显著降低。
2. **多卡张量并行（Tensor Parallelism）的约束：**  
   在进行模型切分时，KV 头数必须能被并行卡数整除。如果模型采用了 8 个 KV 头的 GQA，那么在进行张量并行切分时，最大卡数就被自然限制在了 8 张卡以内，否则一个 KV 头就无法再均分给多个芯片了！

## 步骤 4：精确性能数学公式

单步解码中，不同架构对于单序列的历史 KV Cache 搬运量公式对比（设序列长为 $S$，层数为 $L$，单头维度 $d$）：

$$\text{Bytes}_{\text{MHA}} = 2 \times L \times S \times (H_q \times d) \times 2$$

$$\text{Bytes}_{\text{GQA}} = 2 \times L \times S \times (H_{\text{kv}} \times d) \times 2 = \text{Bytes}_{\text{MHA}} \times \frac{H_{\text{kv}}}{H_q}$$

$$\text{Bytes}_{\text{MQA}} = 2 \times L \times S \times (1 \times d) \times 2 = \text{Bytes}_{\text{MHA}} \times \frac{1}{H_q}$$

$$\text{Bytes}_{\text{MLA}} = L \times S \times (d_c + d_R) \times 2 \quad (\text{其中 } d_c \text{ 为压缩潜在维度, } d_R \text{ 为解耦位置维度})$$

## 步骤 5：具体微基准数字推导

我们以 **70B 参数级大模型**（80 层，$d=128, H_q = 64$），在处理上下文长度 $S = 8192$（8K 文本）时，手算对比四种架构的单用户 KV Cache 显存大小：

### 1. 经典 MHA（$H_{\text{kv}} = 64$）
$$\text{Memory} = 2 \times 80 \times 8192 \times (64 \times 128) \times 2 \text{ 字节} \approx 2.15 \times 10^{10} \text{ 字节} \approx \mathbf{21.47 \text{ GB}}$$
单用户就要吃掉 21.5 GB！一张 80GB 的卡装下模型权重后，连 1 个完整对话都跑不顺畅！

### 2. 现代主流 GQA（$H_{\text{kv}} = 8$，如 LLaMA-3 70B）
$$\text{Memory} = 21.47 \text{ GB} \times \frac{8}{64} = \mathbf{2.68 \text{ GB}}$$
**直接节省了整整 18.8 GB 显存！** 并发容量瞬间提升了 **8 倍**！

### 3. 极致压缩 MQA（$H_{\text{kv}} = 1$）
$$\text{Memory} = 21.47 \text{ GB} \times \frac{1}{64} = \mathbf{0.335 \text{ GB}} \approx 343 \text{ MB}$$

### 4. DeepSeek MLA（$d_c = 512, d_R = 64$）
$$\text{Memory} = 80 \times 8192 \times (512 + 64) \times 2 \approx 7.55 \times 10^8 \text{ 字节} \approx \mathbf{0.755 \text{ GB}}$$
在保持完整多头表征能力的同时，显存只有经典 MHA 的 **3.5%**！

## 步骤 6：核心系统工程铁律

> **模型架构师手中的每一支笔，都直接在芯片硅片上刻下显存烙印。**
