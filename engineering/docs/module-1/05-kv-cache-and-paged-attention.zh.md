# 第 E05 章：KV Cache 显存解剖与 PagedAttention：虚拟内存分页与动态显存碎片治理

## 步骤 1：物理直觉

想象一家拥有 1000 间客房的超级度假酒店：
- **传统静态预分配（Static Allocation）：** 每当一位客人办理入住时，前台根本不知道他会住 1 天还是 30 天。为了保险起见，酒店直接为这位客人把一整层 30 间套房全部挂牌锁定，禁止其他任何人预订。结果：客人实际上只住了一晚就退房了，整座酒店有 80% 的客房长年空置，但新客人却在门口排起长龙，前台频繁报错“客满拒绝接待”！
- **分页虚拟内存管理（PagedAttention）：** 酒店引入了现代智能调度系统。客人办理入住时，前台只给他发一张今晚的房卡（一个页面 Block，包含 16 个房间）。明天如果客人续住，前台在系统中再动态分配任意空闲楼层的下一间客房，并通过一张“虚拟房间索引表”将它们逻辑拼接起来。

在自回归 LLM 推理中，历史 Token 的 Key 和 Value 向量必须被持久缓存（**KV Cache**）。如果没有操作系统般的**分页虚拟内存管理（PagedAttention）**，多达 $60\text{--}80\%$ 的昂贵显存将被静态预分配的空缓冲区和碎片彻底浪费！

---

## 步骤 2：芯片微观底层执行机制

在自回归解码（Decode）阶段，模型每生成 1 个新 Token，只需要将当前新 Token 的 $\mathbf{q}_t$ 与历史所有 Token 的 $\mathbf{k}_{\le t}$ 计算注意力分数，并对 $\mathbf{v}_{\le t}$ 聚合加权。为了避免每步都重新从头计算所有历史词的注意力投影，必须将历史的 Key 和 Value 向量保存在 GPU 显存中，这部分显存被称为 **KV Cache**。

```
传统连续缓存模式 (连续内存分配):
请求 1: [已用 Token: 100] [静态预分配的无用空闲缓冲区: 1948 个位置...] --> 显存浪费率 95%!
请求 2: [已用 Token: 400] [静态预分配的无用空闲缓冲区: 1648 个位置...] --> 无法被其他请求使用
显存物理空间充斥着外部与内部碎片，极大限制了并发并发量 (Batch Size)。

PagedAttention 分页管理模式 (vLLM 架构):
物理显存池 (由固定大小的 Block 构成，例如每个 Block 存放 16 个 Token 的 KV):
物理块 0: [R1: Tok 0-15]     物理块 1: [R2: Tok 0-15]    物理块 2: [R1: Tok 16-31]
物理块 3: [R3: Tok 0-15]     物理块 4: [R2: Tok 16-31]   物理块 5: [空闲块 Free]

块表 (Block Table):
请求 1 (R1) 逻辑页 -> 物理块映射: 逻辑块 0 -> 物理块 0, 逻辑块 1 -> 物理块 2
```

### 核心微观机制：
1. **逻辑地址与物理地址解耦：** 在 CUDA 算子内部，线程束通过读取维护在 SRAM 中的块表（Block Table），将逻辑上连续的序列索引映射为物理显存中离散的内存块指针。
2. **零显存浪费与按需分配：** 只有当一个 Block（例如 16 个 Token）完全写满时，显存管理器才会从空闲池中申请下一个物理 Block。内部碎片被严格限制在最后一个未满的 Block 内部（浪费率 $< 4\%$）。
3. **写时复制（Copy-on-Write）支撑分支生成：** 在并行采样（Parallel Sampling）或束搜索（Beam Search）中，多个候选序列的前缀完全一致。通过让多个逻辑块指向同一个物理块，共享相同历史前缀，显存消耗直接减少 $50\%$ 以上。

## 步骤 3：跨组件相互耦合机制

1. **KV Cache 对在线服务并发批大小的绝对压制：**  
   在推理服务中，GPU 显存总容量固定（如 $80\text{ GB}$）。除去固定的模型权重参数显存外，**剩下的所有显存都属于 KV Cache**。如果每个请求的 KV Cache 占用过大，显存能够容纳的并发请求数（Batch Size）就会被压缩。而批大小越小，解码阶段的算术强度就越低，系统的总体 Token 吞吐率就越惨淡。
2. **长上下文对显存带宽的冲击：**  
   随着生成序列从 1K 延伸到 32K，每一步解码必须从 HBM 读取的 KV Cache 体积扩大了 32 倍。单步解码耗时随上下文长度呈严格线性上升。
3. **结合 GQA 削减缓存体积：**  
   将全头注意力（MHA）改为分组查询注意力（GQA），可以直接将 KV Cache 的物理体积削减至原来的 $\frac{1}{4}$ 或 $\frac{1}{8}$，使系统并发能力直接实现 $4\times$ 到 $8\times$ 的飞跃。

## 步骤 4：精确性能数学公式

单条请求在序列长度为 $S$ 时，KV Cache 所占用的精确物理显存字节数为：

$$
\text{Memory}_{\text{kv}} = 2 \times 2 \times n_{\text{layers}} \times n_{\text{kv\_heads}} \times d_{\text{head}} \times S \quad (\text{字节，在 16 位精度下})
$$

公式各项因子拆解：
- 第一个 $2$：同时缓存 Key 和 Value 两个矩阵；
- 第二个 $2$：FP16 / BF16 每个数值占 2 字节；
- $n_{\text{layers}}$：Transformer 的总层数；
- $n_{\text{kv\_heads}}$：Key 和 Value 的头数（在 MHA 下等于 $n_{\text{heads}}$，在 GQA 下远小于 $n_{\text{heads}}$）；
- $d_{\text{head}}$：注意力单头的特征维度；
- $S$：当前上下文的已处理总序列长度。

对于一个并发批大小为 $B$、平均上下文长度为 $S$ 的推理引擎，全局 KV Cache 总占用为：

$$
\text{Total Memory}_{\text{kv}} = B \times \text{Memory}_{\text{kv}}(S)
$$

最大并发请求支持上限 $B_{\text{max}}$ 为：

$$
B_{\text{max}} = \left\lfloor \frac{\text{显存总容量} - \text{模型权重占用} - \text{运行时系统保留显存}}{\text{Memory}_{\text{kv}}(S_{\text{max}})} \right\rfloor
$$

在传统连续预分配机制下，分母被迫采用 $S_{\text{max}}$；而在 PagedAttention 机制下，分母仅为平均实际序列长度 $\bar{S}$，从而将有效并发容量提升：

$$
\text{并发提升倍率} = \frac{S_{\text{max}}}{\bar{S}} \approx 2\text{--}4\times
$$

## 步骤 5：具体微基准数字推导

以业界主流的 **LLaMA-3 70B**（采用 GQA 架构）在单卡或多卡推理环境下的 KV Cache 消耗手算：
- 模型层数：$n_{\text{layers}} = 80$
- 注意力 Query 头数：$n_{\text{heads}} = 64$
- 注意力 KV 头数：$n_{\text{kv\_heads}} = 8$（由于 GQA，仅为 Query 的 $1/8$）
- 单头维度：$d_{\text{head}} = 128$
- 数据精度：BF16（每元素 2 字节）

### 步骤 5.1：计算单 Token 的 KV Cache 显存增量
每增加 1 个 Token，全模型所有 80 层需要追加缓存的显存为：

$$
\Delta_{\text{token}} = 2 \times 2 \times 80 \times 8 \times 128 = 327,680 \text{ 字节} \approx 320 \text{ KB / Token}
$$

### 步骤 5.2：计算单条长序列请求（$S = 8192$）的显存占用
对于一条上下文长度达到 8K 的请求：

$$
\text{Memory}_{\text{req}} = 8192 \times 320 \text{ KB} \approx 2.62 \times 10^6 \text{ KB} \approx 2.62 \text{ GB}
$$

*注：如果该模型使用的是传统的 MHA（$n_{\text{kv\_heads}} = 64$），则单条请求的 KV Cache 将高达 $2.62 \times 8 = 20.97\text{ GB}$！一条长请求就能吃掉四分之一张 A100！*

### 步骤 5.3：并发与显存利用率对比
假设 8 张 H100 GPU 组网，总可用显存为 $8 \times 80 = 640\text{ GB}$。
- 模型自身权重占用（FP16）：$140\text{ GB}$
- 剩余可用显存空间：$640 - 140 - 20 (\text{系统缓存}) = 480\text{ GB}$

在平均上下文长度 $\bar{S} = 2048$ 条件下（每条请求占用约 $0.655\text{ GB}$）：
- **采用 PagedAttention 时：**
  $$B_{\text{concurrent}} \approx \frac{480 \text{ GB}}{0.655 \text{ GB}} \approx 732 \text{ 个并发请求}$$
- **采用传统静态预分配（按 $S_{\text{max}} = 8192$ 预分配）时：**
  $$B_{\text{concurrent}} \approx \frac{480 \text{ GB}}{2.62 \text{ GB}} \approx 183 \text{ 个并发请求}$$
- **结论：** PagedAttention 让同一套硬件服务器的在线服务承载并发吞吐**瞬间翻了整整 4 倍**，而推理服务的基础设施服务器成本直接降低了 $75\%$！

## 步骤 6：核心系统工程铁律

> 大模型推理的显存管理本质上就是操作系统的虚拟内存管理。谁在自回归服务中为每个请求静态预分配连续的显存缓冲区，谁就在将昂贵的显存带宽和容量白白弃置；将内存切分为固定粒度的小页面并通过页表动态映射，是现代高吞吐推理引擎的生命线。
