## 步骤 1：物理直觉（图书馆霸占一整排座位）

为了让你瞬间理解为什么显存会不够用，老师带你去大学图书馆看一场“占座风波”：

### 传统的显存分配方式（静态预分配）：
假设学校图书馆有一间自习室，里面有一排排连在一起的长桌：
- 来了第一个同学，他说：“老师，我待会儿可能会写一篇长达 2000 字的论文，但我现在才刚刚开始写标题。”
- 图书馆管理员（传统推理引擎）一听，二话不说，**立刻把整整长达 2000 个连在一起的座位全部用封条封上**，只准这位同学一个人坐！
- 哪怕这个同学现在只写了 5 个字、只坐了 1 个座位，其余 1999 个空座位别人也绝对不准碰！
- 这时，外面排队进来了 10 个新同学，自习室里明明放眼望去全是空椅子，但管理员却哭丧着脸说：“对不起，满座了，没有连续的 2000 个空位给你们了，你们去别处吧！”

这就是传统大模型显存分配的荒唐现实——**显存碎片化与过度预留**！实测表明，传统系统中有超过 **60% 到 80% 的显存完全是在为‘可能发生的未来’白白空置**！

### PagedAttention 的巧妙解法（活页笔记本与分页管理）：
既然大家写字都是一个字一个字往后蹦，为什么非要连在一起呢？
- 图书馆给每个同学发一本**活页笔记本**；
- 每当你写满了一张小活页纸（比如放 16 个 Token），管理员就从书架任意角落随便找一个闲置的小抽屉（物理块）给你装这张纸；
- 哪怕这个同学的第 1 页在教室东头、第 2 页在教室西头、第 3 页在地下室，都没关系！管理员手里有一张**“目录索引表（页表）”**，把这些散落的纸按顺序串起来；
- 谁需要空间就给谁一小张，谁写完了就当场撕下来回收！

**自习室的空座率瞬间从 70% 砸到了 0%！原本只能坐 10 个人的房间，现在轻轻松松坐下了 50 个人！**

## 步骤 2：芯片微观底层执行机制

在自回归生成（Decode）阶段，大模型每输出一个新 Token，都需要计算该 Token 的 Query 与历史上所有 Token 的 Key 和 Value 的注意力。

为了避免每吐出一个新字就把上文成千上万个字从头重新算一遍，系统必须在显存中把历史的 $\mathbf{K}$ 和 $\mathbf{V}$ 张量永久缓存起来，这就是 **KV Cache**。

```
传统连续显存分配 (Naive Sequential Cache):
请求 A (预留 2048): [已用 50 个][空闲预留 1998 个 (占着茅坑不拉屎)]
请求 B (预留 2048): [已用 120 个][空闲预留 1928 个 (内存黑洞)]
==> 显存被大块静态切分，外部碎片与内部碎片交织，极易虚假 OOM！

PagedAttention 分页管理 (Block-based Paged Cache):
全局统一的物理块池 (Physical Block Pool, 每个块固定装 16 个 Token):
[物理块 0]  [物理块 1]  [物理块 2]  [物理块 3]  [物理块 4]  [物理块 5] ...

请求 A 的逻辑页表 (Logical Block Table):
  逻辑块 0 ──► 物理块 3 (装第 0~15 个 Token 的 KV)
  逻辑块 1 ──► 物理块 7 (装第 16~31 个 Token 的 KV)
  逻辑块 2 ──► 物理块 1 (当前正在写入第 32~47 个 Token)

请求 B 的逻辑页表:
  逻辑块 0 ──► 物理块 0
  逻辑块 1 ──► 物理块 4
```

### PagedAttention 的内核执行魔法：
在底层的 CUDA 核函数中，线程读取 Key 和 Value 时，不再是简单地根据连续指针偏移量 `ptr + i * stride` 取数据，而是先在共享内存中查阅当前请求的**块映射表（Block Table）**：
1. 计算当前目标 Token 落在第几个逻辑块：$\text{block\_idx} = \lfloor \text{token\_idx} / 16 \rfloor$；
2. 查表得到真实的物理块基地址；
3. 计算物理块内的偏移量：$\text{offset} = \text{token\_idx} \pmod{16}$；
4. 连续取数并送入 Tensor Core 算子。

整个查表过程被完全隐藏在片上共享内存的极低延迟中，对外的计算吞吐**几乎零损耗**！

## 步骤 3：跨组件相互耦合机制

1. **并发批大小（Serving Concurrency）迎来暴增：**  
   消除了显存碎片和静态预留后，原本只能跑 8 个并发的单卡，现在可以稳稳当当塞进 32 到 64 个并发请求，吞吐量（Tokens/s）直接翻了 **3 到 5 倍**！
2. **零开销共享前缀（Copy-on-Write 树状前缀缓存）：**  
   当多个用户问一模一样的问题（例如一段长系统提示词），所有用户可以**共同指向同一组物理 KV 块**！只有当某个用户开始生成自己独有的不同回答时，系统才动态复制分裂出一个新块。这直接让系统提示词的显存开销降为了零！

## 步骤 4：精确性能数学公式

老师带你推导大模型工程师必须倒背如流的 **KV Cache 显存容量公式**。

对于一个大模型：
- 模型层数：$L$（Layers）
- 单头特征维度：$d_k$（Head Dimension）
- KV 注意力头数：$H_{\text{kv}}$（在 MHA 下等于总头数，在 GQA 下远小于总头数）
- 数据精度：$\text{sizeof(dtype)}$（FP16 下为 2 字节，FP8 下为 1 字节）

单个 Token 在单层中需要保存一份 $\mathbf{K}$ 向量和一份 $\mathbf{V}$ 向量：

$$\text{单 Token 单层 KV 大小} = 2 \times H_{\text{kv}} \times d_k \times \text{sizeof(dtype)} \text{ 字节}$$

全模型 $L$ 层，对于一个包含 $S$ 个历史 Token 的请求，其累积占用的 KV Cache 显存绝对值为：

$$\text{KV Cache 容量} = 2 \times L \times H_{\text{kv}} \times d_k \times S \times \text{sizeof(dtype)} \text{ 字节}$$

## 步骤 5：具体微基准数字推导

拿出计算器，跟老师一起来算一算当今最主流的开源王者 **LLaMA-3 70B**！

我们查一查 LLaMA-3 70B 的官方架构参数：
- 层数 $L = 80$
- 总 Query 头数 $H_q = 64$，但它采用了 **GQA 分组查询注意力**，KV 头数只有 $H_{\text{kv}} = 8$！
- 单头维度 $d_k = 128$
- 数据精度：FP16（每元素 2 字节）

### 1. 计算单用户单 Token 的 KV Cache 显存
$$\text{每 Token 显存} = 2 \times 80 \times 8 \times 128 \times 2 = 327,680 \text{ 字节} \approx 320 \text{ KB}$$

你瞧，**用户每说一句话、模型每吐一个字，显存里就多出 320 KB 的永久账单！**

### 2. 计算单用户在 8192（8K）长上下文下的显存占用
$$\text{单请求 KV 显存} = 8192 \times 320 \text{ KB} \approx 2.62 \times 10^6 \text{ KB} \approx 2.62 \text{ GB}$$

### 3. 计算 32 个并发用户同时在线时的显存总账
如果系统同时服务 32 个并发长对话：
$$\text{并发 KV 显存总和} = 32 \times 2.62 \text{ GB} \approx 83.8 \text{ GB}$$

**老师带你分析结果：**  
整整 83.8 GB！这已经超过了一整块 H100 显卡的全部物理容量！  
- 如果采用传统静态分配，由于必须按最大长度为每个请求预留 8K 空间，系统在并发达到 10 的时候就会因为碎片化提前 OOM 暴毙！
- 而采用 **PagedAttention** 后，显存按需分配，实际内存浪费率降至 **4% 以下**，32 个并发请求可以在多卡集群上丝滑流动。

## 步骤 6：核心系统工程铁律

> **动态分页是驯服自回归显存碎片的唯一解。**  
> 绝不静态预留连续显存。通过类似操作系统的逻辑页表与物理块池将 KV Cache 切片化、按需化、共享化，是大模型在线推理服务吞吐翻倍的立足之本。
