## 步骤 2：芯片微观底层执行机制

在混合精度预训练中（以 FP16/BF16 训练、AdamW 优化器为例），一个参数到底会产生多少显存负担？老师带你算这笔著名的 **16P 显存大账本**：

对于一个拥有 $\Phi$ 个参数（Parameters）的大模型：
1. **模型参数（P）：** BF16 格式，占 $2\Phi$ 字节；
2. **反向传播梯度（G）：** BF16 格式，占 $2\Phi$ 字节；
3. **AdamW 优化器状态（O）：** 必须用 FP32 保证数值稳定：
   - FP32 主参数备份：$4\Phi$ 字节；
   - FP32 动量一阶矩 Momentum：$4\Phi$ 字节；
   - FP32 方差二阶矩 Variance：$4\Phi$ 字节；
   - 优化器状态合计：$12\Phi$ 字节！

$$\text{静态训练总显存} = 2\Phi (\text{参数}) + 2\Phi (\text{梯度}) + 12\Phi (\text{优化器}) = \mathbf{16\Phi \text{ 字节！}}$$

```
【ZeRO 家族的三级切片手术刀】

传统 DDP (无分片):
每张卡独立持有: [ 12Φ 优化器状态 ] [ 2Φ 梯度 ] [ 2Φ 参数 ] = 16Φ 纯冗余!

ZeRO-Stage 1 (仅分片优化器状态):
每张卡持有: [ 12Φ / N 优化器状态 ] [ 2Φ 梯度 ] [ 2Φ 参数 ]
==> 显存立减至: 4Φ + 12Φ / N (当 N=8 时，显存降为 5.5Φ，立省 65%!)
==> 额外通信代价: 0! (通信量与传统 DDP 完全相同)

ZeRO-Stage 2 (分片优化器 + 分片梯度):
每张卡持有: [ 12Φ / N 优化器状态 ] [ 2Φ / N 梯度 ] [ 2Φ 参数 ]
==> 显存降至: 2Φ + 14Φ / N (当 N=8 时，显存降为 3.75Φ，立省 76%!)
==> 额外通信代价: 0! (仅将反向 All-Reduce 换为 Reduce-Scatter)

ZeRO-Stage 3 / FSDP (全分片: 优化器 + 梯度 + 模型参数全切碎!):
每张卡仅持有: [ 16Φ / N ] !
==> 显存降至原来的 1 / N ! 显存容量天花板被彻底打破!
==> 额外通信代价: 前向多一次 All-Gather 广播参数，反向多一次 All-Gather 广播参数 (通信量增加 50%)。
```

## 步骤 3：跨组件相互耦合机制

1. **以 50% 额外通信换取无界显存：**  
   ZeRO-3 在前向传播每一层时，必须先通过 All-Gather 把切碎的权重即时拼出来，算完当前层立刻销毁；在反向传播时，再 All-Gather 拼一次算梯度，算完立刻销毁，并用 Reduce-Scatter 散播梯度。这一过程比传统 DDP 增加了 50% 的网络流量。
2. **预取与计算完全重叠（Prefetch Overlap）：**  
   现代 FSDP 实现的精髓在于：**当当前层正在进行前向计算时，后台的通信流已经在悄悄向网线索取下一层的切片参数了（Prefetch）**！只要计算时间大于通信时间，这 50% 的额外网络开销就会被**完全隐藏在物理时间之外**！

## 步骤 4：精确性能数学公式

设模型参数量为 $\Phi$，集群 GPU 卡数为 $N$：

### 1. 单卡静态显存占用对比公式
- 传统 DDP：$M_{\text{DDP}} = 16 \Phi$ 字节
- ZeRO-1：$M_{\text{ZeRO-1}} = 4\Phi + \frac{12\Phi}{N}$ 字节
- ZeRO-2：$M_{\text{ZeRO-2}} = 2\Phi + \frac{14\Phi}{N}$ 字节
- ZeRO-3 / FSDP：$M_{\text{ZeRO-3}} = \frac{16\Phi}{N}$ 字节

### 2. 单步训练通信总量对比（以单向网络传输度量）
- 传统 DDP / ZeRO-1 / ZeRO-2：单步仅需同步梯度一次（All-Reduce），总传输量为：
  $$\text{Comm}_{\text{DDP}} = 2 \Phi \text{ (反向 Reduce-Scatter)} + 0 = 2 \Phi \text{ 字节}$$
- ZeRO-3 / FSDP：
  $$\text{Comm}_{\text{ZeRO-3}} = \underbrace{\Phi}_{\text{前向 All-Gather}} + \underbrace{\Phi}_{\text{反向 All-Gather}} + \underbrace{\Phi}_{\text{反向 Reduce-Scatter}} = 3 \Phi \text{ 字节}$$

**通信量增加比率：** $\frac{3\Phi - 2\Phi}{2\Phi} = 50\%$。

## 步骤 5：具体微基准数字推导

我们来为训练 **LLaMA-3 70B**（$\Phi = 70 \times 10^9$）算一笔震撼人心的显存账本！

单卡物理容量：NVIDIA H100 SXM（80 GB 显存）。
全模型 16P 静态显存底座：
$$16 \Phi = 16 \times 70 \times 10^9 = 1,120 \times 10^9 \text{ 字节} = \mathbf{1,120 \text{ GB}!}$$

### 1. 尝试使用传统数据并行（DDP）：
每张卡必须独立吃下整整 $1,120 \text{ GB}$！单卡才 80 GB，直接超额 **14 倍**！连 1 步都跑不起来！

### 2. 启用 ZeRO-3 / FSDP（部署在 64 张 H100 集群上，$N = 64$）：
每张卡均摊分配 16P 静态负担：

$$\text{单卡静态显存} = \frac{1,120 \text{ GB}}{64} = \mathbf{17.5 \text{ GB}!}$$

**老师带你看奇迹：**  
原本需要 1120 GB 的巨无霸，被 64 张卡均匀拆分后，单卡竟然只占用了区区 **17.5 GB**！  
在 80GB 的显卡上，不仅装得下，还剩下了整整 **62.5 GB** 的超大空间，用于尽情放置长文本和更大 Batch 的激活值！
