## 步骤 2：芯片微观底层执行机制

Ring Attention（Liu et al., 2023）的核心硬件执行机制为：**将序列维度（Sequence Dimension）沿集群 GPU 数量 $N$ 均匀切分，形成环状通信管道！**

```
【Ring Attention 环状执行数据流 (以 4 张 GPU 为例)】

初始状态:
  GPU 0 持有: Q0, K0, V0 (长序列的前 1/4)
  GPU 1 持有: Q1, K1, V1
  GPU 2 持有: Q2, K2, V2
  GPU 3 持有: Q3, K3, V3

执行第 0 步 (本地即时计算):
  各卡在片上计算局部 FlashAttention:
  GPU 0: Attn(Q0, K0, V0) | GPU 1: Attn(Q1, K1, V1) ...

执行第 1 步 (计算与通信完全异步重叠!):
  在后台通过点对点异步通信: K, V 顺时针旋转传递给下一张卡!
  GPU 0 收到 K3, V3 ──► 在前台计算 Attn(Q0, K3, V3) 并在线更新局部输出 O0!
  GPU 1 收到 K0, V0 ──► 在前台计算 Attn(Q1, K0, V0) 并在线更新局部输出 O1!

执行第 2 步与第 3 步:
  持续旋转传递，经过 N-1 步循环后，
  所有 GPU 上的输出向量 O 自动收敛为全序列真实注意力的数学精确解!
```

### 为什么它能实现零通信等待？
因为单块切片的注意力计算时间通常在数十毫秒级别，而通过高速网卡发送一份局部的 $K, V$ 切片只需要几毫秒。  
**传输下一块数据的耗时，被完全包庇、掩盖在当前块密集的张量核心计算轰鸣声中！** 通信开销在物理时间上变成了“隐形人”！

## 步骤 3：跨组件相互耦合机制

1. **单卡显存占用与全序列长度解耦：**  
   单卡上的显存占用不再由全序列长度 $S$ 决定，而仅仅取决于切片长度 $\frac{S}{N}$！只要集群加的卡足够多，理论上可以支持**无限长的上下文窗口（无界百万 Token）**！
2. **因果掩码（Causal Mask）的三角形块剪枝：**  
   在自回归解码或因果预训练中，注意力矩阵是一个下三角阵。在 Ring Attention 旋转中，那些完全位于未来的上三角块（Future Blocks）可以直接在通信或计算中**整块跳过（Skipped）**，进一步节省一半的计算量！

## 步骤 4：精确性能数学公式

设全序列长度为 $S$，集群卡数为 $N$，每个 GPU 处理的序列切片为 $S_{\text{local}} = \frac{S}{N}$。

### 1. 单卡显存占用
单卡只需常驻局部的 Query，以及当前正在计算与正在接收的各两组 Key/Value 缓冲区：

$$\text{Memory}_{\text{ring}} \propto O\left(\frac{S}{N} \times d\right)$$

### 2. 隐藏通信的物理判据
设网络双向点对点带宽为 $B_{\text{p2p}}$，单卡每步传输 $K, V$ 切片的通信耗时为：

$$T_{\text{comm}} = \frac{2 \times \frac{S}{N} \times d \times 2}{B_{\text{p2p}}} = \frac{4 S d}{N B_{\text{p2p}}}$$

单卡在片上执行该分块 FlashAttention 的计算做功耗时为：

$$T_{\text{comp}} \approx \frac{4 \times \left(\frac{S}{N}\right)^2 \times d}{P_{\text{peak}}}$$

只要满足：

$$T_{\text{comp}} \ge T_{\text{comm}} \implies \frac{S}{N} \ge \frac{P_{\text{peak}}}{B_{\text{p2p}}}$$

**通信就会被 100% 完全隐藏！系统达到最高理想吞吐！**

## 步骤 5：具体微基准数字推导

我们来为真实的 **100 万（1,000,000）Token 超长文本** 算一笔硬件账本！

环境：32 张 H100 显卡（$N = 32$），模型为 LLaMA-3 70B（单头维度 $d=128$，头数 $H=64$，机间网卡带宽 $50\text{ GB/s}$）。

### 1. 计算单卡分摊的切片长度
$$S_{\text{local}} = \frac{1,000,000}{32} = \mathbf{31,250 \text{ Token}}$$
单卡只需要处理 3.1 万字，这在单张 80GB 的 H100 显卡上完全是小菜一碟！

### 2. 计算每步通信数据量与耗时
- 单步需搬运当前切片的 K 和 V（以 GQA 8 头计算）：
  $$\text{Bytes} = 2 \times 31250 \times (8 \times 128) \times 2 \approx 128 \text{ MB}$$
- 在 $50\text{ GB/s}$ 的 InfiniBand 网卡上传输耗时：
  $$T_{\text{comm}} = \frac{128 \times 10^6}{50 \times 10^9} \approx 0.00256 \text{ 秒} = \mathbf{2.56 \text{ 毫秒}}$$

### 3. 计算单步本地计算耗时
- 单步浮点运算量约为 $18 \text{ GFLOPs}$，在单卡 Tensor Core 上耗时约为 **$5 \sim 8 \text{ 毫秒}$**。
- **老师请你看结论：**  
  计算耗时（$5\text{ ms}$）明显大于网络通信耗时（$2.56\text{ ms}$）！  
  这意味着**网络传输完全在后台无声无息地跑完，主算力核心没有浪费哪怕一微秒去等数据！百万长文本计算完美达成！**
