# 第 E15 章：张量并行（Megatron-LM）底层实现：列切与行切拆分策略，每层仅两次 All-Reduce 的通信约束

## 步骤 1：物理直觉

想象一块巨大的数学积木，它太沉了，单张显卡根本扛不动。两位工人（两张 GPU）决定合力抬起它：
- **愚蠢的切法：** 每次切下一小片，两人就停下来开会核对一次账目（频繁跨卡通信）。算完一行字开了八次会，工人大部分时间全在等对方汇报。
- **Megatron 优雅的正交切法（列切 + 行切）：**
  - **第一道工序（列切分 Column Parallel）：** 工人 A 和工人 B 各自分头加工左半部分和右半部分。在这道工序里，**双方完全不需要讲话**，各自低头全速干活；
  - **第二道工序（行切分 Row Parallel）：** 两人把刚才加工好的零件拿过来，工人 A 负责收拢前半截，工人 B 负责收拢后半截；
  - **仅在最后交差时刻：** 两人把最终算出的残差数字在桌子中央碰一下（一次 All-Reduce 通信！），立刻就能严丝合缝地拼接出与单张巨型显卡完全一模一样的全局结果！

## 步骤 2：芯片微观底层执行机制

Shoeybi 等人（Megatron-LM, 2019）提出了将 Transformer 内部 GEMM 进行正交切分的经典范式：

```
MLP 层的张量并行实现 (TP = 2):
输入 X [B, S, d] 同时广播至 GPU 0 与 GPU 1

第一步: 列并行线性层 (Column Parallel Linear: W1 拆分为 [W1_1, W1_2])
- GPU 0 计算: Y1 = GeLU(X @ W1_1)   --> 产生局部输出 Y1 [B, S, d_ffn / 2]
- GPU 1 计算: Y2 = GeLU(X @ W1_2)   --> 产生局部输出 Y2 [B, S, d_ffn / 2]
==> 此处完全不需要任何跨卡通信! 各自独立计算!

第二步: 行并行线性层 (Row Parallel Linear: W2 拆分为 [W2_1; W2_2])
- GPU 0 计算: Out1 = Y1 @ W2_1      --> 产生部分和 Out1 [B, S, d]
- GPU 1 计算: Out2 = Y2 @ W2_2      --> 产生部分和 Out2 [B, S, d]
==> 此处各自得到局部的部分和 (Partial Sum)!

第三步: 集合通信 All-Reduce
- Out = All-Reduce-Sum(Out1 + Out2) = X @ W1 @ W2
==> 整个 MLP 模块的前向传播，仅需 1 次 All-Reduce 通信!
```

对于多头注意力层（Self-Attention）：
- $Q, K, V$ 投影矩阵按**列切分**（每个 GPU 分配 $\frac{H}{\text{TP}}$ 个注意力头，各自独立算局部注意力）；
- 输出投影矩阵 $W_O$ 按**行切分**；
- 最终仅在 $W_O$ 输出时执行 **1 次 All-Reduce**！

## 步骤 3：跨组件相互耦合机制

1. **严格限制在单节点 NVLink 内部：**  
   Transformer 每一层需要 2 次 All-Reduce（注意力层 1 次，MLP 层 1 次）。对于一个 80 层的模型，单步前向传播必须连续触发 $160$ 次通信！由于通信处于关键执行路径上，**张量并行度 TP 通常严格限制在 $\text{TP} \le 8$**（即仅在单机 8 卡的 NVLink 环内运行），跨机部署会导致灾难性的网络延迟暴跌。
2. **注意力头数的物理整除约束：**  
   若选择 $\text{TP} = 8$，模型的注意力 Query 头数 $H$ 与 GQA 的 KV 头数 $G$ 必须能够被 8 整除。如果一个架构只有 6 个 KV 头，直接设置 $\text{TP} = 8$ 将引发硬件断言报错！

## 步骤 4：精确性能数学公式

对于隐藏层维度为 $d$、序列长度为 $S$、批大小为 $B$、张量并行度为 $\text{TP}$ 的单层 Transformer：

### 显存占用降低：
$$\text{单卡权重显存} = \frac{\text{层总权重显存}}{\text{TP}}$$

### 每层通信数据量（前向传播）：
每一层包含 2 次 All-Reduce，每次传输大小为 $B \times S \times d$ 的激活值张量：

$$\text{单层前向通信量} = 2 \times \left( 2 \cdot \frac{\text{TP} - 1}{\text{TP}} \cdot (2 B S d) \right) \text{ 字节 (FP16)}$$

当 $\text{TP} = 8$ 时：

$$\text{通信量} = 4 \times \frac{7}{8} \times (2 B S d) = 7 B S d \text{ 字节 / 层}$$

反向传播中同样产生 2 次 All-Reduce，因此整网训练每步通信量为 $14 B S d$ 字节/层。

## 步骤 5：具体微基准数字推导

以 LLaMA-3 70B（$d = 8192, n_{\text{layers}} = 80$）在单机 8 卡 H100（$\text{TP} = 8$），批大小 $B = 4$，序列长度 $S = 4096$ 下前向传播通信开销：

1. **单次 All-Reduce 激活值张量大小：**
   $$M = 4 \times 4096 \times 8192 \times 2 \text{ 字节} = 268.4 \text{ MB}$$
2. **单层 2 次 All-Reduce 实际走过的通信总线流量：**
   $$\text{单层流量} = 2 \times \left(2 \times \frac{7}{8} \times 268.4 \text{ MB}\right) \approx 939.4 \text{ MB}$$
3. **全模型 80 层累计总前向通信量：**
   $$\text{全模型通信总量} = 80 \times 939.4 \text{ MB} \approx 75.15 \text{ GB}$$
4. **在 NVLink（有效单向带宽 $450\text{ GB/s}$）下的物理通信总耗时：**
   $$T_{\text{comm}} = \frac{75.15 \times 10^9}{450 \times 10^9} \approx 0.167 \text{ 秒} = 167 \text{ 毫秒}$$
- **结论：** 若在没有 NVLink 的普通 PCIe 服务器上执行该操作，通信耗时将暴增至 **2.3 秒** 以上，系统完全丧失实时推理与训练价值。

---

## 步骤 6：核心系统工程铁律

> 优秀的分布式并行设计，本质是对通信拓扑的极致精简。Megatron-LM 的精髓在于通过“列切 + 行切”的正交数学共轭，将庞大的中间激活值通信完全闭环在片内，将每层的全局通信强行压缩至仅仅两次 All-Reduce，锁定了单机超高速互联的物理红利。
