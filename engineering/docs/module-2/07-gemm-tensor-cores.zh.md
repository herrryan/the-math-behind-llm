## 步骤 1：物理直觉（铁匠打铁与汽车冲压车间）

为了让你秒懂普通计算核心与 Tensor Core 的区别，老师打一个制造业的比方：

- **普通标量/向量核心（CUDA Core）：老铁匠手工打铁**  
  老铁匠站在铁砧前，左手夹着一块铁，右手抡起铁锤：叮（一次乘法）、当（一次加法）。打完一颗铁钉，再去打下一颗。虽然他手艺精湛、什么形状都能敲（支持各种复杂分支逻辑），但一次只能做 1 件事。
- **Tensor Core（张量核心）：重型汽车冲压机床**  
  车间里立着一台重达千吨的液压冲压机。工人们不再一锤一锤敲，而是把整块 $16 \times 16$ 大小的整块钢板推进去，机械臂“轰隆”一声巨响齐齐压下，**一瞬间把 256 个零件的乘加融合运算（$D = A \times B + C$）在几个时钟周期内全部冲压成型！**

你看，冲压机虽然威力极其毁天灭地，但它有一个极其严苛的脾气：**模具尺寸必须绝对精准匹配！**

如果你的零件尺寸是长 16、宽 16，刚好卡进模具槽里，冲压机就能满负荷连续疯狂轰鸣；  
但如果你的零件长了个毛边，比如尺寸是 17 或者 15，零件卡不进模具槽，冲压机就会当场卡壳停机！工人不得不把冲压机切回慢吞吞的手工锯模式，速度瞬间暴跌 90%！

这就是为什么在 AI 工业界，工程师们会对**“16 字节对齐”、“维度必须是 8 或 16 的倍数”**有种近乎强迫症一般的执着。

## 步骤 2：芯片微观底层执行机制

在 NVIDIA Volta、Ampere、Hopper 架构中，Tensor Core 的微观硬件执行采用的是**流水线矩阵乘累加（MMA，Matrix Multiply-Accumulate）指令**：

```
MMA 指令基本做功单元: D = A x B + C
输入矩阵分块: A 尺寸 [M x K], B 尺寸 [K x N], 累加器 C/D 尺寸 [M x N]

【Warp 线程束协同分块机制 (以 16 x 8 x 16 为例)】
Warp 内的 32 个线程并不各自独立算一个大矩阵，
而是像交织的齿轮一样，把一个 16 x 16 的微小矩阵切片分配进 32 个线程的内部寄存器中:
  - 线程 0~3 负责持有矩阵 A 的第 0 行片段与矩阵 B 的第 0 列片段；
  - 硬件内部的微型脉动阵列在 1 个周期内完成乘法广播并进入加法累加器树；
  - 经过多级流水线，生成高精度的 FP32 或 FP16 结果存入寄存器堆。

【三级 GEMM 分块平铺层次 (Tiling Hierarchy)】
┌──────────────────────────────────────────────────────────────────┐
│ 1. 网格级分块 (Grid-level): 整个大 GEMM 矩阵切分为 128x256 的大块 │
│    分配给不同的 SM (Streaming Multiprocessor) 独立并行处理        │
├──────────────────────────────────────────────────────────────────┤
│ 2. 线程块级分块 (Block-level): 每个 SM 从全局 HBM 搬运数据至      │
│    片上共享内存 (SRAM), 维持持续的循环流水线 (Pipelines)          │
├──────────────────────────────────────────────────────────────────┤
│ 3. 线程束级分块 (Warp-level): 每个 Warp 独占从 SRAM 抓取 16x16 块 │
│    直接送进 Tensor Core 的 MMA 指令冲压流水线                      │
└──────────────────────────────────────────────────────────────────┘
```

### 为什么维度必须对齐？
- Tensor Core 的硬件指令（例如 `mma.sync.aligned.m16n8k16`）严格要求矩阵的内层跨度 $K$ 必须是 16 的倍数（在 FP16 精度下对应 32 字节，恰好填满单次寄存器向量读取）。
- 如果大模型的隐藏层维度 $d_{\text{model}}$ 没有被 16 或 128 整除，底层编译器就无法生成高效的 MMA 矢量指令，只能降级为低速标量指令，或者插入大量低效的零填充（Padding），造成极大的算力浪费。

## 步骤 3：跨组件相互耦合机制

1. **大模型超参数设计的“硬件暗门”：**  
   你仔细观察过主流开源大模型（如 LLaMA、Mistral、Qwen）的结构参数吗？它们的隐藏层维度（如 4096、8192）、注意力头数（如 32、64）、单头维度（128）**无一例外全是 16 和 128 的整倍数**！这不是巧合，而是架构师们为了完美契合 Tensor Core 冲压模具而特意裁定的物理黄金尺寸。
2. **张量切分与分布式通信的契约：**  
   当进行多卡张量并行（Tensor Parallelism）时，矩阵会被横向或纵向切分。如果并行卡数是 8，切分后的子矩阵必须依然能被 16 整除，否则单卡上的 Tensor Core 执行效率就会骤降。

## 步骤 4：精确性能数学公式

对于一个通用的矩阵乘法（GEMM）：

$$\mathbf{C} = \mathbf{A} \times \mathbf{B}$$

其中 $\mathbf{A} \in \mathbb{R}^{M \times K}, \mathbf{B} \in \mathbb{R}^{K \times N}, \mathbf{C} \in \mathbb{R}^{M \times N}$。

### 1. 浮点运算量（FLOPs）
每个位置的输出需要做 $K$ 次乘法和 $K$ 次加法（共 $2K$ 次浮点做功），全矩阵总运算量为：

$$\text{FLOPs}_{\text{GEMM}} = 2 \times M \times N \times K$$

### 2. 在理想分块下的 HBM 搬运量（Bytes，设精度为 2 字节 FP16）
若片上 SRAM 完美复用，每块数据从 HBM 仅读取一次：

$$\text{Bytes}_{\text{GEMM}} = 2 \times (M \times K + K \times N + M \times N) \text{ 字节}$$

### 3. GEMM 的理论算术强度（Operational Intensity）
$$I_{\text{GEMM}} = \frac{2 \times M \times N \times K}{2 \times (MK + KN + MN)} = \frac{M \times N \times K}{MK + KN + MN}$$

当 $M, N, K$ 都非常巨大（如均等于 $D$）时：

$$I_{\text{GEMM}} \approx \frac{D^3}{3 D^2} = \frac{D}{3} \text{ FLOPs/Byte}$$

**老师划重点：**  
随着矩阵尺寸 $D$ 的扩大，算术强度呈线性上升！只要矩阵足够大，$I_{\text{GEMM}}$ 就会轻松跨过屋顶模型的硬件平衡点 $I^*$，让 Tensor Core 全力发挥出理论最高性能！

## 步骤 5：具体微基准数字推导

拿出计算器，我们来算一算 **LLaMA-3 70B** 在 Prefill 阶段的一个线性层 GEMM！

参数设置：
- 批大小与序列长度乘积：$M = 4096$
- 输入维度：$K = 8192$
- 输出维度：$N = 8192$
- 硬件：NVIDIA H100 SXM（FP16 峰值算力 $1,000 \text{ TFLOPS}$，HBM 带宽 $3.35 \text{ TB/s}$，平衡拐点 $I^* \approx 298.5$）

### 1. 计算总做功 FLOPs
$$\text{FLOPs} = 2 \times 4096 \times 8192 \times 8192 \approx 5.497 \times 10^{11} \text{ FLOPs} \approx 550 \text{ GFLOPs}$$

### 2. 计算理想 HBM 搬运量
- 输入矩阵 A：$4096 \times 8192 \times 2 \approx 67.1 \text{ MB}$
- 权重矩阵 B：$8192 \times 8192 \times 2 \approx 134.2 \text{ MB}$
- 输出矩阵 C：$4096 \times 8192 \times 2 \approx 67.1 \text{ MB}$
- 总访存：$\text{Bytes} = 67.1 + 134.2 + 67.1 = 268.4 \text{ MB} \approx 0.268 \text{ GB}$

### 3. 计算实际算术强度 $I$
$$I = \frac{5.497 \times 10^{11} \text{ FLOPs}}{2.684 \times 10^8 \text{ Bytes}} \approx 2048 \text{ FLOPs/Byte}$$

### 4. 判断硬件工况
因为 $2048 \gg 298.5$（是平衡拐点的将近 7 倍！），该算子深深落入**纯计算受限区间（Compute-Bound）**！
- 理论物理纯计算耗时：
  $$T_{\text{compute}} = \frac{5.497 \times 10^{11}}{1.0 \times 10^{15}} \approx 0.00055 \text{ 秒} = 550 \;\mu\text{s} = 0.55 \text{ ms}$$
此时，Tensor Core 的冲压机被彻底喂饱，硬件利用率可以冲上 70%~80% 的极高水准！

## 步骤 6：核心系统工程铁律

> **顺应 Tensor Core 的冲压模具，把矩阵做大、排整齐。**  
> 永远确保张量维度是 16 与 128 的倍数以触发硬件级 MMA 向量指令；在 Prefill 阶段尽可能合并 Batch 增大矩阵尺寸，让算术强度跨过平衡拐点，榨干芯片的每一滴浮点算力。
