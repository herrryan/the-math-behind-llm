# 第 E23 章：MoE 系统架构：Top-K 门控与容量因子：激活参数与总参数解耦，专家容量超载丢弃策略

## 步骤 1：物理直觉

想象一个拥有一所包含 64 位专科医生的大型综合医院：
- **稠密模型（Dense）：** 每来一位感冒发烧的普通病人，医院居然把全院所有 64 位专科医生（心血管、眼科、神经科、皮肤科）同时召集进同一个诊室，所有人一起给病人把脉问诊！虽然诊断很周全，但医院每分钟的开销极其恐怖，诊室里人挤人彻底堵死。
- **混合专家模型（MoE）：** 医院门诊大厅设立了一位经验丰富的**分诊护士（门控路由 Top-K Gating）**。病人进门后，护士看一眼病情，快速挑选最擅长的 **2 位专家**（例如呼吸科专家 A 和 B）接诊，其余 62 位专家在各自办公室休息或接待其他病人！

每个病人的开销直接降低为原本的 $\frac{2}{64} \approx 3\%$！但这里隐藏着一个物理危机：**如果全城突然爆发流感，所有病人都挤着去找呼吸科专家，呼吸科诊室门口排起长龙，而其他诊室全部闲置（专家负载失衡）**。此时，医院必须设定一个**专家容量上限（Capacity Factor）**，超出负荷的病人必须被分流或暂缓挂号！

## 步骤 2：芯片微观底层执行机制

MoE（Mixture of Experts）将大模型中参数量最大的 FFN 层替换为一组由门控网络（Router）路由的独立专家模块：

$$
\mathbf{y} = \sum_{i \in \text{TopK}(G(\mathbf{x}))} g_i(\mathbf{x}) \cdot \text{Expert}_i(\mathbf{x})
$$

```
MoE 门控路由与专家调度:
输入 Token 序列: X [B*S, d]
       │
       ▼
[门控路由网络 Router: x @ W_gate] ──► 产出 Softmax 路由分数
       │
       ▼
[Top-K 算法挑选最高分的前 K 个专家 (如 Top-2)]
       │
       ├── Token 分流与重排 (Token Dispatch / Scatter)
       ▼
┌──────────────────┬──────────────────┬──────────────────┐
│  专家 0 (FFN_0)  │  专家 1 (FFN_1)  │  ... 专家 E-1    │
│  处理属于自己的   │  处理属于自己的   │                  │
│  Token 批次      │  Token 批次      │                  │
└────────┬─────────┴────────┬─────────┴────────┬─────────┘
         │                  │                  │
         └── Token 汇聚与加权累加 (Token Combine / Gather)
```

### 物理痛点：专家容量因子（Capacity Factor，CF）
GPU 硬件的 GEMM 算子极其依赖规则、固定尺寸的张量输入。如果专家 0 接收到了 100 个 Token，而专家 1 只分到了 2 个 Token，硬件流水线将发生严重的负载倾斜。  
为此，系统设置**专家容量（Expert Capacity）**：

$$\text{Capacity} = \left\lceil \frac{B \times S \times K}{E} \times \text{CF} \right\rceil$$

- 当某个专家分配到的实际 Token 数超出该阈值时，超出部分将被直接**丢弃（Dropped Tokens）**或通过残差连接直接绕过计算；
- 在模型训练中，必须引入**辅助负载均衡损失（Load Balancing Auxiliary Loss）**，在数学上惩罚门控将请求扎堆给少数专家的行为。

## 步骤 3：跨组件相互耦合机制

1. **显存总容量与激活参数的物理割裂：**  
   对于一个总参数量 236B、每次仅激活 21B 的 MoE 模型（如 DeepSeek-V2）：
   - 在**计算开销（FLOPs）**上：它仅等同于一个 21B 的轻量小模型；
   - 但在**显存容量（HBM Capacity）**上：它必须完整常驻整整 236B 的全部权重（即使没被调用的专家也必须在显存里占用空间）！
2. **训练反向传播的梯度稀疏性：**  
   未被激活的专家在当次迭代中梯度为 0，只有当批次累加足够大时，才能保证所有专家的参数得到充分更新。

---

## 步骤 4：精确性能数学公式

设模型包含 $E$ 个专家，每次激活 $K$ 个专家，FFN 参数量为 $P_{\text{ffn\_expert}}$：

全模型 FFN 的总静态参数量：

$$P_{\text{total\_moe}} = E \times P_{\text{ffn\_expert}}$$

单 Token 前向传播实际消耗的有效参数量（激活参数量）：

$$P_{\text{active\_moe}} = K \times P_{\text{ffn\_expert}} = P_{\text{total\_moe}} \times \left(\frac{K}{E}\right)$$

其单 Token 计算量比同规模稠密模型缩减为：

$$\text{FLOPs 压缩比} = \frac{K}{E}$$

当 $E = 64, K = 2$ 时：

$$\text{FLOPs 压缩比} = \frac{2}{64} = \frac{1}{32} \approx 3.125\%$$

**MoE 用完全相同的计算算力消耗，支撑起了高达 32 倍的庞大知识库容量！**

## 步骤 5：具体微基准数字推导

对比 16 个专家的 MoE 模型（总参数量 $16 \times 7\text{ B} \approx 112\text{ B}$，每次激活 $K = 2$ 个专家，等效激活参数量约为 $14\text{ B}$）：
- 硬件：单台 8 卡 H100（每卡 $80\text{ GB}$，总显存 $640\text{ GB}$）
- 序列批大小：$B \times S = 2048$ 个 Token

### 1. 静态显存占用：
- 全模型在 FP16 下必须完整装入：
  $$\text{Memory} \approx 112 \times 2 = 224 \text{ GB}$$
- 8 张卡完全可以容纳该静态权重（每卡分摊 $28\text{ GB}$）。

### 2. 算力开销对比：
- 若这是一个普通的 112B 稠密模型，每 Token 需做约 $224\text{ GFLOPs}$ 运算；
- 而该 MoE 模型每 Token 仅需做：
  $$\text{FLOPs} = 2 \times 14 \times 10^9 = 28 \text{ GFLOPs}$$
- **计算提速：单步推理耗时缩短了整整 $8\times$ 倍！**  
  系统在具备千亿模型智能深度的同时，享受着百亿级小模型的飞速生成体验。

---

## 步骤 6：核心系统工程铁律

> 混合专家模型的本质，是用低廉的静态显存容量去置换昂贵的动态浮点算力。处理 MoE 系统的核心不在于专家内部的 GEMM，而在于门控路由的负载均衡与容量因子截断控制，防止局部硬件在热点倾斜中陷入长尾阻塞。
