同学，你好！热烈欢迎来到《大语言模型背后的工程实现》课程！

如果说在前面的《数学篇》中，我们像数学家一样，用优美的公式推导出了大模型的大脑“在想什么”；那么在《工程篇》里，老师将带你穿上工装、戴上防静电手环，亲自走进轰鸣作响的真实数据中心，去看看**这颗数学大脑是如何在一块块滚烫的硅基芯片上真实转动起来的**。

## 老师的课前开场白：为什么只懂数学还远远不够？

很多刚接触大模型的同学经常会问老师这样一个困惑的问题：

> “老师，我在草稿纸上写下了一个完美的 Transformer 公式，用 PyTorch 几行代码就实现了。可为什么当我把模型部署到显卡上时，显卡要么直接报出 <samp>CUDA out of memory (OOM)</samp> 崩溃罢工，要么几百万元买来的顶级算力芯片，利用率居然只有可怜的 15%？”

答案就在于：**物理世界是有摩擦力的，计算机硬件是有物理极限的。**

在纯数学里，符号只是纸面上的字符，相乘一次不需要耗费电能，相加一次不需要等待时间，写下一个 $100000 \times 100000$ 的大矩阵只需要在纸上画两个方括号。

但在现实的 GPU 芯片上：
- 每一个数字，都是由物理电荷或微小电容在硅片上存储的；
- 每一个运算，都需要通过铜互连导线把数据从冷库（显存 HBM）运送到灶台（寄存器与 Tensor Core）；
- 如果你的运输车队（显存带宽）跑得太慢，哪怕你雇佣了全世界切菜最快的米其林大厨（顶级算力），大厨也只能无奈地坐在案板前发呆打瞌睡。

这就是大模型系统工程的迷人之处：**它是一门在严酷的物理限制与算法之间走钢丝的极致艺术。**

```
                            [物理现实的三重约束]

                               [算力 COMPUTE]
                         Tensor Core 脉动做功单元
                       (主厨的挥刀速度: 2,000 TFLOPS)
                                    ▲
                                   / \
                                  /   \
                                 /     \
                                /       \
                               /         \
                              ▼           ▼
                       [显存 MEMORY] ◄──► [通信 INTERCONNECT]
                         HBM / SRAM         NVLink / 交换机网络
                  (冷库搬菜带宽: 3.35 TB/s)  (跨机运货带宽: 900 GB/s)
```

在这门课中，老师不会向你生硬地罗列冷冰冰的技术手册，而是像朋友一样，把每一个看似高深莫测的硬核概念（FlashAttention、PagedAttention、张量并行、1F1B、RoPE 熔合），用你听得懂的大白话、直观的生活比方，以及手把手的数字推导，彻底给你讲得明明白白。

## 贯穿全课程的四大核心系统谜题

在这趟探索旅程中，老师会带着你逐一解开困扰现代 AI 工业界的四大终极谜题：

1. **为什么算力越强的芯片，反而越容易“挨饿”？（屋顶模型 Roofline）**  
   老师会带你拿起秒表和量尺，算一算一个算子究竟是在“疯狂算”，还是在“苦苦等”。你将第一次看懂为什么有的算子优化哪怕减少了一半乘法，运行时间却纹丝不动。
2. **为什么注意力机制会撞上“显存粉身碎骨墙”？（FlashAttention 的救赎）**  
   序列长度从 2K 变成 32K，显存占用为什么会爆炸 256 倍？老师将带你看看天才研究员是如何通过“不留中间草稿纸、在心算中完成在线归一化”的神奇手法，拯救了长文本大模型。
3. **为什么几百人同时和大模型聊天，显卡会突然爆仓？（PagedAttention 虚拟内存）**  
   你将发现，传统的显存管理就像去图书馆霸占一整排空座位，浪费率高达 80%！老师会带你手写一个操作系统级别的页表管理器，把每一寸显存都压榨到极致。
4. **千亿级大模型塞不进单张卡，怎么让上千张显卡像交响乐团一样协同？（分布式并行）**  
   矩阵怎么切？通信怎么藏？流水线中间的气泡怎么挤出来？我们将拆解 Megatron、DeepSpeed 和 FSDP 的底层原语，带你掌握大规模分布式集群的排兵布阵之道。

## 课程体系大纲（八大进阶模块）

老师为你精心规划了由浅入深、层层递进的 8 个核心模块，步步为营，没有一座攀不上的陡坡：

1. **[模块 0：硬件图景与物理底座](module-0/00-silicon-anatomy.zh.md)**  
   拆开芯片看结构：寄存器、SRAM 与 HBM 的物理速度鸿沟；屋顶模型的数学推导；合并访存为什么要求数据排得像操场阅兵一样整齐。
2. **[模块 1：芯片层级的注意力子系统](module-1/03-naive-attention-memory-wall.zh.md)**  
   朴素注意力的显存灾难；FlashAttention 1、2、3 的分块与流水线重叠；KV Cache 的显存账本；MHA、GQA 与 MLA 的工程权衡大对决。
3. **[模块 2：线性层、激活函数与内核熔合](module-2/07-gemm-tensor-cores.zh.md)**  
   张量核心（Tensor Core）的脉动阵列冲压机；SwiGLU 为什么吃掉全网 66% 的算力；Fused RMSNorm 如何省下两趟显存往返；RoPE 为什么要在寄存器里即时转动。
4. **[模块 3：数值格式、计算精度与量化架构](module-3/11-number-formats-fp8-bf16.zh.md)**  
   浮点数的放大镜：FP32、FP16、BF16 与 FP8 的阶码尾数取舍；W8A8 与 W4A16 量化如何让小显存撬动大模型；KV Cache 的低比特压缩。
5. **[模块 4：分布式系统拓扑与并行扩展](module-4/14-distributed-communication-primitives.zh.md)**  
   集合通信三大神器（All-Reduce、Reduce-Scatter、All-Gather）；Megatron 张量并行的行切与列切；1F1B 流水线并行如何消除等待气泡；ZeRO 与 FSDP 的无界显存切分；百万长上下文的 Ring Attention 环状通信。
6. **[模块 5：高吞吐推理引擎与在线调度](module-5/19-prefill-vs-decode-regimes.zh.md)**  
   Prefill（吃算力）与 Decode（吃显存带宽）的两大截然不同世界；连续批处理（Continuous Batching）如何消灭填充留白；投机解码如何让小弟跑腿、大哥掌舵；分块预填与前缀缓存的妙用。
7. **[模块 6：混合专家模型（MoE）工程架构](module-6/23-moe-routing-capacity-factor.zh.md)**  
   Top-K 门控路由器如何挑出天选专家；容量因子与超载丢弃策略；跨机 All-to-All 交换机网络的拥堵治理与算网重叠。
8. **[模块 7：系统审计、显存精算与 MFU 性能评测](module-7/25-model-memory-budget.zh.md)**  
   训练 16P 静态显存的严密账本推导；激活值重计算的“算力换显存”交易；模型算力利用率（MFU）的科学测量与 Nsight 工具链实战。

## 4 个硬核系统实战工坊（Hands-on Labs）

光听老师讲还不够，真正的工程师必须亲手闻一闻代码和硬件碰撞的火药味！课程配套了 4 个由零手写的实验：

- **[实验 E1：GPU 屋顶模型自动化分析器](labs/01-roofline-profiler.zh.md)**  
  带你写一个纯 Python 工具，测量任何一个 PyTorch 函数的真实做功与搬运，亲手在坐标轴上画出它离硬件天花板还有多远。
- **[实验 E2：极简 FlashAttention 算子实现](labs/02-flash-attention-kernel.zh.md)**  
  使用 Triton 编写一个迷你版注意力算子，把中间巨大的分数矩阵从显存里彻底抹去，亲眼见证数倍的速度跃升。
- **[实验 E3：PagedAttention 分页内存管理器](labs/03-paged-kv-cache.zh.md)**  
  从零手写虚拟内存分配表，把散落在显存各个角落的缓存碎片规整串联，支撑起高并发的自回归生成。
- **[实验 E4：双卡张量并行（Tensor Parallelism）手搓引擎](labs/04-tensor-parallel-engine.zh.md)**  
  亲手把一个大矩阵拆成两半，分别扔进两张显卡，用通信原语精准协同计算，体验千亿集群的基本单元是怎么跑起来的。
